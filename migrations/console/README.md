# SQL за конзолата на D1

Готови за копиране файлове, ако предпочиташ да пуснеш схемата от
Cloudflare Dashboard вместо с `wrangler`.

Път в таблото: **Storage & Databases → D1 → vibeship-db → Console**.

| Файл | Кога |
|---|---|
| `billing.sql` | Базата вече има таблиците на платформата (`users`, `apps`…) и трябват само таблиците за абонаменти и кредити. |
| `full_schema.sql` | Базата е празна. Съдържа цялата схема наведнъж. |

И двата файла са с `IF NOT EXISTS` навсякъде, така че повторно пускане не чупи нищо.

## Кой път да избереш

`full_schema.sql` е генериран от `worker/database/schema.ts` с `drizzle-kit export`
— крайното състояние, без междинните стъпки на миграциите. Затова е подходящ
само за празна база: не съдържа `ALTER TABLE` стъпките, с които по-старите
миграции преобразуват вече съществуващи таблици.

След ръчно пускане тук `wrangler` не знае, че схемата е налична. Ако после
пуснеш `bun run db:migrate:remote`, той ще опита да приложи миграциите отново:
заявките за таблици и индекси ще минат безобидно, но `ALTER TABLE` стъпките в
`0001`, `0002`, `0006` и `0007` ще гръмнат, защото колоните вече ги има.

Затова: избери един път и се придържай към него.

- **Само конзолата** — при всяка следваща промяна на схемата генерирай нова
  миграция с `bun run db:generate` и пускай новия `.sql` файл в конзолата.
- **Само wrangler** (препоръчително) — `bun run db:migrate:remote`; тогава тези
  файлове ти трябват най-много за справка.

## Обновяване на файловете

```bash
bunx drizzle-kit export --dialect=sqlite --schema=./worker/database/schema.ts
```
